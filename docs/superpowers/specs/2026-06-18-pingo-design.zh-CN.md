# Pingo 设计文档

日期：2026-06-18

## 目标

Pingo 是一个使用 Tauri 和 Rust 构建的可分发桌面监控工具。它会检测一组可配置 IPv4 地址的可达性，记录每次 ping 的结果，并用可交互柱状图展示延迟历史。

首个版本面向 macOS 和 Windows。它应该能作为普通桌面应用运行，让非开发者用户直接使用。

## 范围

首个版本包含：

- macOS 和 Windows 桌面构建。
- 仅支持 IPv4 目标。
- 手动添加、编辑、启用、禁用和删除目标。
- 批量导入目标（支持 `IP,别名` 格式，别名可选）。
- 每个目标支持一个用户可见别名。
- 全局 ping 启动/停止控制。
- Ping 运行状态可视化（toolbar 背景渐变流动动画）。
- 全局 ping 间隔和 ping 超时配置。
- ping 间隔默认 5 秒。
- ping 超时默认 5 秒。
- 基于本地 SQLite 的数据文件。
- 在应用数据目录中自动管理默认数据文件。
- 打开外部数据文件进行只读历史浏览。
- 可配置历史保留时长，默认 7 天。
- 目标重复超时时显示应用内告警状态。
- Overview-first 仪表盘，每个目标显示 IP、别名、平均延时、已发送次数、超时次数、超时率，以及启用/禁用开关。
- 目标列表支持排序（按 IP、添加时间、延迟），支持升序/降序切换。
- 单个选中目标的详情视图，支持缩放、平移和时间轴导航。
- 柱状图依据窗口自动缩放，图例显示在图表外部。

首个版本不包含：

- IPv6、域名或主机名目标。
- 目标分组或标签。
- CSV、图片或 PDF 导出。
- 系统通知。
- 对用于历史浏览的外部数据文件进行写入。

## 架构

应用使用 Tauri 作为桌面外壳。Rust 负责 ping 执行、调度、配置、持久化，以及暴露给前端的 API。前端负责目标管理界面、图表渲染、设置，以及历史数据的交互式浏览。

后端模块：

- `ping`：macOS 和 Windows 的平台适配层。每个适配器调用系统 `ping` 命令，并把输出解析成共享结果类型。
- `scheduler`：按照当前全局间隔和超时设置，在全局 Ping 启动后协调所有已启用目标的周期性 ping。
- `storage`：读写 SQLite 数据文件，包括默认当前监控文件和只读外部历史文件。
- `config`：持久化用户设置，例如目标列表、别名、间隔、超时、保留期和告警阈值。
- `commands`：用于查询和修改目标、设置、历史数据的 Tauri 命令。
- `events`：每次 ping 采样后，从 Rust 向前端发送实时结果事件。

推荐实现方案是系统 `ping` 加 SQLite。这样可以避免可分发桌面应用常见的 raw ICMP 权限问题，同时让历史查询和保留期清理保持高效。

## 数据模型

SQLite 文件保存监控历史和目标元数据。

`targets`：

- `id`：稳定的目标标识符。
- `ipv4`：IPv4 地址字符串。
- `alias`：用户可见名称。
- `enabled`：该目标是否参与 ping（需全局 Ping 启动后才生效）。
- `created_at`：创建时间戳。
- `updated_at`：最后更新时间戳。

`ping_samples`：

- `id`：采样标识符。
- `target_id`：关联目标。
- `sent_at`：ping 尝试的时间戳。
- `status`：成功、超时或错误。
- `latency_ms`：成功时测得的延迟。
- `error_kind`：失败时的标准化错误类别。

默认当前数据文件保存在应用数据目录中。应用也允许用户打开外部数据文件进行只读查看。首个版本不会写入外部文件。

## 运行行为

应用启动时加载设置和默认当前数据文件，此时 Ping 处于停止状态。用户点击「启动 Ping」后，调度器开始 ping 所有已启用目标；点击「停止 Ping」后，调度器停止所有 ping 操作。每个 ping 结果会写入当前 SQLite 文件，并发送给前端。

只有同时满足「全局 Ping 已启动」和「目标为启用状态」两个条件，该目标才会被 ping。禁用目标不会丢失已有历史数据。

当用户修改目标或设置时，前端调用 Tauri 命令。后端持久化变更，并在不重启应用的情况下重新加载调度器配置。

删除目标会停止该目标后续采样。已有历史仍保留在数据文件中，方便回看过去的结果。

保留期清理会移除早于配置保留期的采样。默认保留期是 7 天。

告警仅在应用内显示。目标连续超时次数达到配置阈值后进入告警状态。默认阈值是连续 3 次超时。告警状态会在仪表盘中以视觉方式展示，例如红色状态样式和提示信息。

## 用户界面

主布局采用 overview first。

顶部工具栏：

- 添加目标。
- 批量导入目标（支持每行一个 IP，可选格式：`IP,别名`）。
- 文件管理菜单（新建监测、打开监测、另存为、清空历史数据）。
- 设置。
- 启动 Ping / 停止 Ping（根据当前状态切换显示）。
- Ping 运行状态可视化：当 Ping 运行时，toolbar 显示清新淡雅的绿色渐变背景，并有光效流动动画。

总览仪表盘：

- 目标以卡片网格展示。
- 目标列表顶部包含排序控件：排序方式下拉框（按 IP、添加时间、延迟）和升序/降序按键（↑/↓）。
- 每张卡片显示 IPv4 地址、别名，以及平均延时、已发送 ping 次数、超时次数、超时率等统计数据。
- 每张卡片包含一个启用/禁用开关，只有开启的目标在全局 Ping 启动后才会被检测。
- 正常、超时和告警状态需要有明确视觉区分。
- 支持多选功能：Cmd + 点击逐个选择，Shift + 点击范围选择。
- 右键点击卡片弹出上下文菜单：编辑、启用/禁用、删除。

详情视图：

- 选中目标后，打开或展开该目标的大型柱状图。
- 柱状图依据窗口大小自动缩放，图例显示在图表外部。
- 详情图支持缩放、平移和时间轴移动。
- 详情区域显示当前可见范围内的基础统计，例如平均延迟、最大延迟和超时次数。

设置面板：

- ping 间隔秒数，默认 5。
- ping 超时秒数，默认 5。
- 历史保留天数，默认 7。
- 连续超时告警阈值，默认 3。

目标编辑器：

- IPv4 地址。
- 别名。

## 错误处理

用户可见错误应该不依赖开发背景也能理解。

示例：

- IPv4 地址无效：说明首个版本仅支持 IPv4。
- ping 命令失败：提示该目标无法检测，并让调度器继续处理其他目标。
- 数据文件打开失败：说明该文件无法打开，或不是受支持的 Pingo 数据文件。
- 存储写入失败：显示应用级警告，因为监控历史可能无法保存。

后端错误在传给前端前应该标准化，避免 UI 依赖平台特定命令输出。

## 测试策略

Rust 测试：

- 解析代表性的 macOS `ping` 输出。
- 解析代表性的 Windows `ping` 输出。
- 标准化成功、超时和错误情况。
- 向 SQLite 写入并读取 ping 采样。
- 按目标和时间范围查询采样。
- 清理早于配置保留期的采样。
- 在目标或设置变化后重新加载调度器状态。

前端和集成检查：

- 添加、编辑、禁用和删除目标。
- 在总览网格中显示实时 ping 结果更新。
- 以只读模式打开历史数据文件。
- 从历史文件返回当前监控文件。
- 缩放和平移详情图。
- 达到配置的连续超时阈值后显示应用内告警状态。

手动发布检查：

- 在 macOS 上运行。
- 在 Windows 上运行。
- 使用普通用户权限验证打包应用行为。

## 未来扩展

该设计刻意固定首个实现计划的范围。核心应用可用后，后续版本可以增加 IPv6、主机名支持、CSV 导出、系统通知、批量导入和目标分组。
